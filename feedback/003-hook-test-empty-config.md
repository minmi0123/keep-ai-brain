```yaml
상태: 반영 (main 5e4f7dc) — guard.mjs 에 자가시험 문자열 keep-ai-brain-guard-selftest 내장

출처: 집 PC 첫 설치. 사용자가 Q6 에서 강제 push 차단도 끔 (토이 repo 라 필요 없다고 판단)
대상: SETUP.md:51 (Q6), SETUP.md:98 (2-5 2번), SETUP.md:110 ("deny 가 나오면 된다")
심각도: 하 — 지금 막는 게 없으니 당장 피해는 없음. 나중에 패턴을 추가했을 때 hook 이 아예 안 돌고 있었다는 걸 늦게 알 수 있음
```

## 증상

- 2-5 확인 기준이 "deny 가 나오면 된다" 뿐이다. 목록이 전부 빈 배열이면 어떤 입력도 통과하므로 hook 이 붙어 있는지, 돌아가는지 확인할 수 없다
- 2-5 2번은 "강제 push 막기는 남기는 것이 기본" 이라고만 하고, 사용자가 이것까지 끈 경우의 확인 절차가 없다

## 이번에 한 것

- 설치본(빈 목록)에는 통과만 확인
- repo 의 예시 guard.config.json 을 임시 폴더에 guard.mjs 와 같이 복사해 deny 가 나오는지 따로 확인

## 제안

- 2-5 확인에 "목록이 비었으면: 예시 설정 사본으로 차단 동작을 확인하고, 설치본은 통과만 확인한다" 추가 (002 의 시험 스크립트가 `--config` 를 받게 하면 간단)
- 4장 보고 표의 hook 칸에 "차단 목록 비어 있음 — 지금은 아무것도 막지 않음" 을 쓰게 안내
