# kb — 재사용 지식 인덱스

> 이 폴더는 **AI 가 읽고 쓰는 뇌**다. 사람이 읽기 좋은 형태가 아니라 **AI 가 찾기 좋은 형태**로 쓴다.
> 규칙마다 "왜" 는 keep-ai-brain `docs/why.md` 에 있다.

## 사용 규칙

1. **새 문서 작성 전 이 INDEX 를 먼저 검색**한다. 유사 문서가 있으면 새로 만들지 말고 기존 문서에 추가한다
2. 문서를 추가하면 **INDEX 에 한 줄 추가**한다. 한 영역 문서가 많아지면 `INDEX-{영역}.md` 하위 목차를 만들고 여기엔 그 목차 한 줄만 둔다
3. 트러블슈팅은 영역과 무관하게 전부 `trouble/` 에 모은다
4. frontmatter 필수: `title / category / tags / summary / created / updated`
5. 문서를 추가·이동한 뒤에는 **점검 도구를 돌린다** (아래)
6. **INDEX 한 줄은 150자 이내** — 주제 + 언제 여나 + 찾을 키워드만. 숫자·세부는 문서 `summary` 에. **INDEX·하위 목차는 각각 40KB 아래로**

## 문서 작성 원칙 (AI 탐색 기준)

| # | 원칙 | 이유 |
|---|---|---|
| 1 | **한 사실은 한 곳에만.** 중복 대신 링크 | 검색 결과가 둘이면 "어느 게 최신?" 을 매번 판단해야 하고, 한쪽만 고치면 조용히 불일치가 생긴다 |
| 2 | **문서 하나 = 주제 하나** (기능 1개 = md 1개). 제목에서 "언제 읽을지" 가 드러나게 | 제목만 보고 열지 말지 정할 수 있어야 한다. 섞이면 소제목 축이 무너진다 |
| 3 | **금지·주의는 문서 맨 앞에** | 앞부분이 확실히 읽힌다. 뒤에 묻으면 놓친다 |
| 4 | 본문 첫 줄에 `> 언제 읽나: ...` | INDEX 를 거치지 않고 열었을 때의 판단 근거 |
| 5 | 서술문 최소화 → 표 · YAML · bullet | 파싱과 인용이 쉽다 |
| 6 | 경로는 `파일:줄` 까지 | 바로 열 수 있다 |
| 7 | 다른 문서를 복사하지 말고 **재구성** | 사람용 문서를 그대로 옮기면 AI 탐색 이점이 없다 |
| 8 | frontmatter 에 `source` / `source_checked` | 원본(코드·문서)이 바뀌었을 때 재확인 기준 |
| 9 | **파일명 = 주제 이름.** 날짜를 붙이지 않는다. 날짜는 frontmatter 에만 | AI 는 파일명으로 검색한다. 날짜를 붙이면 같은 주제 문서가 여러 개 생긴다 |
| 10 | **문서 하나는 50KB 안쪽.** 넘으면 "지금 상태" 본문과 "경위·실측 기록" 이력 문서(`{이름}_history.md`)로 나눈다 | 한 번에 못 읽는 크기가 되면 AI 가 앞부분만 읽고 판단한다. 경위가 길수록 지금 상태가 묻힌다 |
| 11 | **본문 = 지금도 사실인 것만.** 바뀐 사실은 바뀌는 그때 `_history` 로 옮기고, 본문 그 자리에 `(YYYY-MM 전엔 X → 경위: [history](…))` 한 줄만 남긴다. 사실에는 확인 날짜를 붙인다. 끝난 진행판은 결과 요약만 남기고 나머지를 history 로. 코드·로그·질문에서 다시 만날 일이 없는 것은 지운다(git 에 남는다). 구성이 통째로 바뀌면(서버 이전 등) 옛 구성을 `{이름}_pre-{사건}.md` 로 옮기고 맨 위에 "언제까지 유효, 지금은 쓰지 않음" | AI 는 검색에 걸린 줄을 현재 사실로 믿는다. 옛 값이 본문에 섞이면 크기보다 위험하다. 한 줄 단서는 옛 값이 옛 코드·로그에서 다시 보일 때 헛짚지 않게 한다 |

> 내용을 다른 문서로 옮겼으면 원래 자리에 **`→ 정본: [문서](경로)`** 한 줄만 남긴다. 본문을 양쪽에 두지 않는다.

## 작성 관행

| 관행 | 방식 |
|---|---|
| 주의 요약 | `> 언제 읽나` 바로 아래 `**먼저 볼 주의**` bullet 3~5개. 상세 내용은 본문 한 곳에만 |
| 문서 단위 | 기능 1개 = md 1개. 영역 지도(여러 기능을 한 줄씩 훑고 정본 링크)만 예외. 애매하면 AI 가 정하고 이유를 보고 |
| 불확실 표시 | 확인 못 한 것은 추측하지 않고 `[확인필요]`. 다른 문서와 코드가 다르면 `[문서-코드 불일치]` → 자동 질문 목록에 모인다 |
| 확인 표시 | ✅ 코드·DB 로 확인 / 🔶 추정 |
| 기준 표시 | `source` 에 근거(코드 실측·문서·실제 경험)와 가능하면 커밋, `source_checked` 에 확인 날짜 |
| 비밀값 | 위치만 적고 **값은 옮기지 않는다**. 민감 정보가 든 문서는 frontmatter 에 `sensitive: true` |
| 이슈 | 분석 중 발견한 문제는 기능 문서의 「이슈」 절에 `\| # \| 내용 \| 위치 \| 상태 \|` 표로. 절 제목에 **"이슈"** 또는 "결함" 을 넣어야 이슈 대장이 모은다. 고칠지는 사람이 정한다 |
| 편집 | 파일 편집 도구로. `sed` 로 줄을 옮기거나 지우지 않는다 |
| git 반영 | 수정 → `check-kb.cjs` → **내가 고친 파일만** `git add` → `git commit`. `commit -a`·`add -A` 금지 (여러 세션이 동시에 고친다) |

## 점검 도구

- 문서를 고친 뒤 `node _tools/check-kb.cjs` — 깨진 링크·frontmatter·CRLF·크기·INDEX 누락·150자. 자동 목록(질문·이슈)도 다시 만든다
- 뇌 전체(kb·메모리·작업 폴더): `node _tools/check-brain.cjs` — 주간 자동 점검이 이것을 부른다
- 자동 목록은 **고치지 않는다** — 원래 문서를 고치고 다시 만든다. 묶음 폴더는 검색에서 빠진다(`.ignore`)
- 기준값·경로: `_tools/config.json`
