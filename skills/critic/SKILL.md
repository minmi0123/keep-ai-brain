# /critic — 비판 검토 (④)

입력: `$ARGUMENTS`

같은 AI 가 쓰고 같은 AI 가 검토하면 놓치는 곳도 같다. 그래서 이 검토는 **넓게 보지 않고 좁게 본다** — 기계(테스트·전/후 비교)가 못 보는 것만, 근거가 있는 것만, 반박을 견딘 것만 남긴다.

> 경로: `{KB}`·`{TASKS}` 의 실제 위치는 CLAUDE.md 「keep-ai-brain 경로」 표를 따른다.

## 절대 규칙

```yaml
코드_수정: 금지. 소스·설정을 고치지 않는다. 산출물은 보고서 md 1개
근거_필수: 지적마다 파일:줄(diff 쪽) + 패턴 번호(C01 등). 둘 중 하나라도 없으면 버린다
반박_통과만: 후보 지적은 5단계 반박을 거쳐 살아남은 것만 보고한다
diff_범위: diff 가 만들거나 건드린 줄만 지적한다. diff 밖 기존 문제는 "참고" 칸에만
독립성: 개발 세션의 대화·설명을 근거로 쓰지 않는다. 읽는 것은 diff·기준표·kb·소스뿐. 같은 세션에서 개발한 직후라면 보고서 머리에 "독립성 낮음"을 적는다 (가능하면 새 세션에서 돌린다)
수정_제안: 고치는 방법은 한 줄 방향만. 패치 코드를 쓰지 않는다
DB: 운영 DB 에 접속하지 않는다. 실행 확인이 꼭 필요하면 보고서에 "실행 확인 필요"로 남기고 사용자에게 넘긴다
개인정보: 보고서에 값을 옮기지 않는다 (컬럼명·위치까지만)
```

## 경로

| 이름 | 위치 |
|---|---|
| 체크리스트 (기준) | `{KB}/ops/review-checklist.md` |
| 이슈 대장 (켰으면) | `{KB}/ops/issues.md` → `issues/{묶음}.md` |
| 보고서 | 작업 폴더가 있으면 `{작업 폴더}/critic-{YYMMDD-HHMM}.md`, 없으면 `{TASKS}/critic/{YYMMDD-HHMM}-{대상}.md` |

## 입력 해석

| 인자 | 뜻 | 없으면 |
|---|---|---|
| `{저장소}:{범위}` | git 범위·커밋·브랜치. 커밋 하나면 `{커밋}^..{커밋}`(머지 커밋이면 `^1`) | 현재 저장소의 현재 브랜치 vs 기본 브랜치의 merge-base |
| `{저장소}:작업트리` | 커밋 전 변경. `git diff HEAD`(스테이지 포함) + `git status --porcelain` 의 새 파일(`??`) 전체 | — |
| `파일={경로}` | git 밖 파일(운영 반영 스크립트 등). 여러 번 쓸 수 있고 와일드카드 가능. 파일 전체를 "추가된 줄"로 본다 | — |
| `기준표=경로` | ① 판정 기준표 md | 6단계를 건너뛰고 보고서에 "기준표 없음 — 요구 해석 오류는 검토 못 함" |
| `시험` | 과거 커밋 시험 모드 (아래) | 일반 모드 |

범위가 애매하면 묻지 말고 `git log --oneline` 으로 후보를 보여 준 뒤 가장 그럴듯한 것으로 진행하고 보고서에 적는다.

## 순서

### 1. 대상 확정
- `git diff --stat {범위}` 로 파일 목록 (작업트리면 `git diff HEAD --stat` + 새 파일, `파일=` 이면 그 목록). 빌드 산출물(`build/`·`dist/`·`out/` 등)은 뺀다
- `파일=` 로 받은 스크립트는 diff 가 없으니, 스크립트가 건드리는 테이블·객체의 **지금 정의**를 "전"으로 삼아 무엇이 바뀌는지 먼저 정리한다
- 바뀐 파일을 종류로 나눈다: 진입점(Controller·라우터)·서비스·데이터 접근(쿼리·ORM)·모델·DB 객체·화면·설정

### 2. 기준 읽기
- 체크리스트를 **끝까지** 읽는다. 검토 순서·빠른 검색 표가 이 스킬의 기준이다
- 체크리스트가 비어 있거나 없으면 일반 위험 범주(돈·개인정보·권한 / 데이터 정합·상태 / 표시·집계·성능)로 보고, 보고서에 "체크리스트 없음" 을 적는다

### 3. 영향 범위
- 바뀐 화면·API·함수마다 호출하는 쪽을 찾고, 바뀐 테이블·DB 객체는 그것을 쓰는 곳을 찾는다
- **형제 찾기**: 바뀐 함수와 이름이 비슷한 것, 같은 계산을 하는 곳을 검색. diff 가 한 벌만 고쳤으면 후보로 올린다
- 이슈 대장을 켰으면 그 기능의 기존 이슈를 확인한다

### 4. 후보 뽑기
- diff 의 **추가·수정 줄**에 체크리스트의 빠른 검색 표를 돌린다
- 바뀐 함수는 diff 조각만 보지 말고 **본문 전체**를 열어 심각도 높은 패턴부터 대 본다 (트랜잭션·예외 처리·호출한 함수의 반환값은 diff 밖에 있다)
- 운영 반영 스크립트면 kb 에 팀 DB 변경 규칙 문서가 있으면 그것도 대 본다 (롤백 가드, WHERE 없는 UPDATE/DELETE, 감사 컬럼 등). 규칙 위반은 패턴 번호 대신 `규칙` 으로 표시한다
- 후보마다 `패턴 · 파일:줄 · 의심 이유 한 줄` 로 적어 둔다

### 5. 반박 (후보마다)
후보를 **틀렸다고 가정**하고 반증을 찾는다. 하나라도 성립하면 버린다.

| 반박 질문 | 예 |
|---|---|
| 호출하는 쪽·호출되는 쪽이 이미 막는가 | 서비스가 로그인 사용자로 덮어씀, 쿼리에 상태 조건 있음 |
| 그 경로가 실제로 도는가 | 호출하는 곳 0, 특정 환경에서만 켜짐 |
| diff 전에도 똑같았나 | 그렇다면 지적이 아니라 "참고 — 기존 문제" |
| 원래 패턴과 정말 같은 모양인가 | 체크리스트의 예시를 열어 대조 |

- 후보가 10개를 넘으면 반박을 서브에이전트에 나눠 맡겨도 된다. 이때 서브에이전트에는 **후보·파일 경로·체크리스트 경로만** 주고, 이 세션의 판단 근거는 주지 않는다
- 살아남은 지적은 심각도를 다시 정한다: 체크리스트 등급이 기본이고, 실제 영향 범위(3단계)를 보고 한 단계까지 올리거나 내린다. 바꾸면 이유를 적는다

### 6. 기준표 대조 (기준표가 있을 때)
- 기준표의 행(입력 → 기대 결과)마다 diff 가 그 결과를 내는 경로를 따라가 **충족 / 미충족 / 판단불가** 를 매긴다
- 기준표에 없는데 diff 가 바꾼 동작이 있으면 "기준표 밖 변경" 으로 적는다 (요구를 넘어선 변경)

### 7. 보고서 쓰기
위 경로에 아래 양식으로 쓴다. 채팅에는 판정·지적 표만 붙인다 (사용자가 md 를 못 열 수도 있다).

```markdown
---
title: 비판 검토 — {대상}
created: YYYY-MM-DD HH:MM
target: {저장소:범위 ...}
mode: 일반 | 시험
criteria: {기준표 경로 | 없음}
independence: 높음 | 낮음(같은 세션에서 개발)
---

# 비판 검토 — {대상}

## 판정
- 결과: 머지 보류(C 있음) | 수정 요구(H 있음) | 통과(M 이하)
- 바뀐 파일 N · 후보 N → 지적 N (버린 후보 N)

## 지적
| # | 심각도 | 패턴 | 위치 | 내용 | 근거·재현 | 고칠 방향 |
|---|---|---|---|---|---|---|

## 기준표 대조
| 기준 행 | 결과 | 근거 |
|---|---|---|

## 참고 — diff 밖 기존 문제
| 문제 | 이 변경과의 관계 |
|---|---|

## 버린 후보
| 패턴 | 위치 | 버린 이유(반박 질문) |
|---|---|---|

## 확인 못 한 것
- 실행이 필요한 것, 접근 못 한 소스 등
```

## 시험 모드 (과거 버그 커밋으로 거꾸로 재기)

목적: "이 검토가 실제 버그를 미리 잡았을까"를 숫자로 잰다. 체크리스트를 믿어도 되는지 확인하는 방법이다.

1. 사용자가 **버그를 만든 커밋**을 준다. 버그 내용·고친 커밋은 사용자나 별도 세션이 갖고 있고, **이 세션에는 알려 주지 않는다**
2. 그 저장소에서 그 커밋 기준으로 일반 순서 1~7을 그대로 돈다. **checkout 하지 않는다** — 그 시점 파일은 `git show {커밋}:{경로}`, 형제 찾기는 `git grep {패턴} {커밋}` 으로 본다. 그 커밋 **이후** 이력(`git log {커밋}..`)과 kb 에서 그 버그를 직접 설명하는 문서는 열지 않는다 — 정답 보기다
3. 보고서 frontmatter `mode: 시험`. 채점은 사용자가 정답과 대 보며 한다: 잡음 / 비슷한 위치를 짚음 / 놓침, 그리고 오탐 수
4. 여러 커밋을 돌려 "N건 중 M건 미리 잡음" 으로 모은다. 놓친 버그의 모양은 체크리스트에 새 신호로 더한다

## 끝낼 때

- 보고서 경로와 판정을 한 줄로 알린다
- 지적이 0이면 "지적 없음"과 버린 후보 수, 검토하지 못한 범위를 함께 말한다 (0 = 안전 이 아니다)
