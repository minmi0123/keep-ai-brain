# /kb-harvest — 대화에서 kb 에 남길 것 거두기

compact 하거나 새 세션으로 넘어가면 대화 속 사실은 사라진다. 작업 폴더(이어하기·이력)는 그 일이 끝나면 안 읽힌다. **다음에 다른 일을 하다가도 필요한 사실**은 kb 에 있어야 한다. 이 스킬은 대화에서 그것만 골라 kb 의 맞는 자리에 넣는다.

> 경로: `{KB}`·`{TASKS}` 의 실제 위치는 CLAUDE.md 「keep-ai-brain 경로」 표를 따른다.

## 지킬 것

```yaml
형식_정본: "{KB}/INDEX.md" 의 "사용 규칙"·"문서 작성 원칙"·"작성 관행" — 여기 다시 적지 않는다. 시작할 때 그 세 절을 읽는다
창작_금지: 이번 대화에서 코드·DB·데이터·사용자가 준 자료로 확인한 것만. 대화 중 추정은 빼거나 🔶 표시
개인정보: 화면·쿼리 결과 속 다른 사람의 이름·번호·아이디·이메일은 옮기지 않는다. 비밀값(비밀번호·토큰·키)은 위치만 적고 값은 쓰지 않는다
이슈: 발견한 문제는 kb 에 기록한다. 고칠지는 사람이 정한다 — 이번 작업 범위 밖이면 고치지 않는다
kb_재량: 구조·자리·새 문서 여부는 묻지 않고 정한 뒤 보고한다. 사용자가 "먼저 보여줘" 하면 계획에서 멈춘다
커밋: 끝나면 바로 커밋한다. 이번에 고친 파일 + 점검 도구가 다시 만든 목록만 add — commit -a·add -A 금지 (여러 세션이 동시에 kb 를 고친다)
편집: 파일 편집 도구로. sed 로 줄을 옮기거나 지우지 않는다 (표 한 행이 조용히 사라진 사고가 있었다)
```

## 1. 주제 나누기

대화를 처음부터 훑어 주제별로 나눈다. 주제 = 기능 하나, 사고 하나, 업무 하나. 사용자가 범위를 정하면("방금 로그인 얘기만") 그 주제만 본다.

| 주제 | 근거로 본 것 (코드·DB·화면·메시지) | kb 후보 |
|---|---|---|

## 2. 후보 고르기

| 넣는다 | 예 |
|---|---|
| 코드·DB 로 확인한 동작, 특히 **설계와 실제가 다른 것** | "재전송은 UPDATE" 로 짰지만 실제로는 늘 INSERT |
| 이슈·위험 (파일:줄 근거) | 제한 조건이 NULL 비교라 늘 통과 |
| 사고·장애의 경위·원인·조사 방법 | 조사 쿼리와 결과 읽는 법 |
| 실측값 (출처·날짜를 붙여서) | 운영 설정값, 데이터 건수 |
| 해소된 `[확인필요]` | 원래 자리를 해소 표시로 |
| 대화 중 틀렸다가 바로잡은 사실 | kb 에 틀린 채 적혀 있으면 그 줄을 고친다 |
| 코드만으론 모르는 업무 뜻·팀 방식 | 회의·메시지에서 들은 것 |

| 뺀다 | 어디로 |
|---|---|
| 진행 중인 결정·초안·일정·기준표 | 작업 폴더 `{TASKS}/…`. kb 에서는 경로를 글자로만 가리킨다 |
| 설명용 비유·일반 지식 (HTTP 원리 등) | 버린다 |
| 확인 안 된 추정 | 버리거나, 꼭 필요하면 🔶 |
| 사용자 성향·작업 방식 | 메모리 (compact-confirm) |
| 사람 평가·잡담 | 버린다 |

## 3. 넣을 자리 정하기

1. **있는지 찾기** — INDEX 와 kb 전체를 파일명·테이블·함수·클래스·화면 이름으로 검색. 있으면 그 문서에 덧붙인다
2. **대상 문서 최신 확인** — `git -C {KB} log -3 --format="%h %ad %s" --date=short -- {문서}` 와 작업트리 변경. 오늘 다른 세션이 고쳤으면 그 내용을 읽고 대화 결론과 부딪히지 않는지 본다. 코드도 최신 커밋으로 다시 확인한다
   - **고치기 전 `git -C {KB} status --short` 를 적어 둔다.** 이미 M 인 파일은 다른 세션이 작업 중인 것이다 — 그 파일은 되도록 피하고, 꼭 고쳐야 하면 5장 커밋에서 빼고 보고한다 (내 변경과 남의 변경이 한 파일에 섞이면 따로 커밋할 수 없다)
   - 대화 속 "아직 안 바뀌었을 것" 이, 다른 세션이 먼저 반영해 둔 변경 때문에 틀린 적이 있다
3. **자리**

| 후보 | 자리 |
|---|---|
| 이슈 | 그 기능 문서의 「이슈」 표 다음 번호. 문서 앞 "먼저 볼 주의" 에도 한 줄 |
| 사고·트러블 | `trouble/` 새 문서 + 기능 문서에서 링크 |
| kb 에 없는 기능의 사실 | `overview/` 새 문서 (기능 1개 = 문서 1개) + INDEX 한 줄 (영역 하위 목차 `INDEX-{영역}.md` 가 있으면 거기) |
| 코드 패턴·규약 | `patterns/` |
| 리뷰 때 잡을 신호 | `ops/review-checklist.md` 의 맞는 패턴에 신호 추가 |
| 업무 용어·규칙 | `overview/glossary.md` |
| 팀 방식 | `ops/team-process.md` |

4. 계획을 표로 한 번 보여 주고 바로 진행한다.

## 4. 반영

- frontmatter `updated`·`source`·`source_checked` 를 고친다. `source` 에 이번 근거(커밋·실측·사용자 제공 자료)를 덧붙인다
- 해소는 원래 줄을 `해소 (YYYY-MM-DD, 근거): …` 로 고친다. 본문에 "확인 필요" 같은 말을 새로 쓰면 질문 목록에 잘못 잡힌다
- 관련 문서끼리 링크 한 줄씩 (정본은 한 곳)

## 5. 점검과 보고

1. `node {KB}/_tools/check-kb.cjs` — 깨진 링크·frontmatter 0 확인. 다시 만들어진 자동 목록(`ops/open-questions*`·`ops/issues*`)은 커밋 대상에 넣는다. 내가 안 고친 파일의 경고는 건드리지 않고 보고만
2. `git -C {KB} diff --stat` 과 지운 줄(`git diff | grep '^-'`)이 의도한 것뿐인지
3. 작업 폴더 문서에 이번에 바로잡은 사실이 틀린 채 있으면 고친다
4. 작업이 끝난 폴더면 이어하기.md 에 `kb 반영: 완료 (YYYY-MM-DD)` 한 줄 (작업 폴더 점검기가 이 줄을 본다)
5. **커밋**
   - `git -C {KB} status --short` 를 3장에서 적어 둔 것과 비교해, **이번에 내가 바꾼 파일과 자동 목록만** `git add <경로…>`
   - 3장에서 이미 M 이던 파일(다른 세션 작업 중)은 넣지 않는다. 자동 목록이 남의 변경까지 반영했으면 자동 목록도 빼고 보고한다
   - 메시지: 한 줄, `{주제} 반영 — {문서별 바꾼 것 요약}`
   - 커밋 뒤 `git status --short` 로 내 파일이 남지 않았는지 본다
6. 보고

```markdown
| 문서 | 바꾼 것 |
|---|---|

뺀 것: 진행 중 결정 N건(작업 폴더에만), 설명용 비유 등
점검: 깨진 링크 0 · frontmatter 0
커밋: {해시} {메시지} (파일 n개) / 빼고 둔 파일: {다른 세션 작업 중인 파일}
```
